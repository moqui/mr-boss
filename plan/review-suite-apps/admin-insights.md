# Review: design-admin.md and design-insights.md

Reviewer pass, Nov 1, 2026, of the Oct 31, 2026 drafts. Checked against research-admin.md, research-insights.md, design-crosscut.md, every app's Settings and Reports sections, the framework tools apps and moqui-report, and the reference apps. Paths are relative to the mr-moqui repository root unless the report gives a shorthand; reference-app paths are under `~/work/moquiwork/3p_other/`. The coordinated decisions and dispositions are in [review-suite-apps.md](../review-suite-apps.md); this file is the reviewer's report as delivered.

1. **Summary**

- **Accurate against current code.** Nearly every load-bearing framework, Mantle and BOSS name in both files exists in active XML. Neither file proposes a second dashboard, alert, scheduler or incident engine. Most findings are about depth: contracts with only one side, security edges, and capability the framework already has but the designs don't use or (FlowMap) rebuild.
- **The crosscut §6.4 reconciliation was only partly applied in the app files.** The Oct 31 commit (ebd46c0) touched People, Maintenance, Projects, Purchasing, Sales, Warehouse, Accounting and Commons. It did not touch Products, Commerce, Marketing, Customer Service or Manufacturing. As a result:
  - Shared/DataImport has no consumer in any app file. Products' import is already built separately.
  - The People→Admin provisioning call is named by neither side.
  - Five apps' report sections don't mention the Insights catalog.
- **Admin has four security gaps:**
  - The mail-relay list covers every `EmailServer`, including each user's personal-mailbox server and its credentials.
  - Changing a connection's host keeps its stored secret, so the secret goes to the new host.
  - The new instance-wide permissions are not sealed, and the Admin bundles are not privileged groups.
  - Staff invitations have no acceptance route.
- **Insights' release depends on L-sized framework work it doesn't size.** No group schedule or business alert ships until recipient execution (INS-06/07) and dataset admission (INS-03) exist. A new dataset returns nothing until a DataFeed indexes it, and no step does that. Scope policies reinvent the existing `rowFilterService`.
- **Ownership conflicts remain:**
  - Gateway config: Admin claims the native PaymentGatewayConfig, ShippingGatewayConfig and TaxGatewayConfig records, but crosscut §5 gives the tax gateway to Accounting.
  - Mail aliases: Comms says Admin creates them; Admin only lists them.
  - Employee360: the owner tables carry an Admin row, though Admin doesn't mount it, and no Insights row, though Insights does.
  - Two SalesAnalysis reports (Accounting's built one and Sales') call the same service.
- **Admin builds what exists or links to what doesn't.** Its §13 links point at System/Llm agent screens that don't exist (no AgentDefinition editor, no A2A tasks screen, no gateway key shown once). It re-specifies Tools job, message, localization and audit screens without saying which delegated need forces that. ~10 new `org.moqui.admin.*` framework service families are proposed with no phasing, and every row is first-release (`new`/`parity`).
- **Both Open lists are empty** and both status lines claim "final"/"specification". The guide wants decisions with recommendations in Open; at least eight per file belong there (§8).
- **Most important fixes:** R-ADM-01/02/03/04/05/06, R-INS-01/02/03, and the cross-app decisions in §7.
