# Review: design-people.md and design-maintenance.md

Reviewer pass, Nov 1, 2026, of the Oct 31, 2026 drafts. Checked against research-people.md, research-maintenance.md, design-crosscut.md, the core-app designs, design-doc-guide.md §11, active Mantle XML and the reference apps. Paths are relative to the mr-moqui repository root unless the report gives a shorthand; reference-app paths are under `~/work/moquiwork/3p_other/`. The coordinated decisions and dispositions are in [review-suite-apps.md](../review-suite-apps.md); this file is the reviewer's report as delivered.

1. **Summary**

- **The other apps don't reflect these two contracts.** Both designs set up their handoffs carefully, but the other apps' files don't match them. Manufacturing still records equipment-fault downtime itself and never mentions Maintenance's outage record, ResourceUnavailability. Accounting has no MaintenanceCostPolicy, and no rule that hides payroll invoices, payments and ledger lines from general finance users. Purchasing never mentions maintenance requests or outside-service acceptance. People's checklists ignore the shared process engine (MT-03), even though crosscut and Maintenance both say People reuses it.
- **Existing Mantle code on the designed paths is not named.**
  - The CalDAV Tasks collection already lists every assigned WetTask. A phone task app can mark one complete, which writes `WorkEffort.statusId` directly. That skips Maintenance's checklist and evidence gates and People's protected tasks.
  - `RequestTriageNotice` and `complete#RequestFromWork` run on the grievance Request path.
  - `WorkEffortPartyAssignedNotify` and `WorkEffortStartCompleteDates` run on step and checklist tasks.
  - `TIME_ENTRY_RATE` is already granted to `BOSS_PROJECT_MANAGER`, and every TimeEntry stores the worker's own pay rate.
- **Some existing names don't do what the designs assume.**
  - PartySkill, EmplPositionClassSkill and WorkEffortSkillStandard have no level, evidence or date fields.
  - EmplPosition has no department field, and `create#Employment` refuses a position whose organization is not the employer.
  - `create#ProjectExpenseInvoice` already works without a project.
  - Asset has no warranty field.
- **People ↔ Maintenance has three gaps.**
  - Technician skills and availability: Maintenance never calls People's `check#Qualifications`, the capacity service or the existing `find#StaffingCandidates`.
  - Equipment custody at separation: Employee360 has no equipment pane, and no file owns the return step.
  - Labor cost: Maintenance's cost report would show each person's pay rate, which People forbids. The two files need one labor costing rate.
- **The shared-screen registry is missing rows for sensitive mounts.**
  - People: the confidential grievance RequestDetail, payroll InvoiceDetail, EquipmentDetail, InterviewsCalendar, and the five Projects time screens People mounts.
  - Maintenance: Employee360, OrderDetail and InventoryAvailability.
- **Both designs build things that already exist.** Their import wizards duplicate Admin's Shared/DataImport, which crosscut §6.4 already settled. HR files have no registered content hosts (the same problem as R-XC-05). Maintenance re-guards facility writes that `store#Facility` already guards.
- **Scope.** People marks about 20 native-payroll screens as first-release `new`, yet says no localization exists and live payroll is blocked. Ship the external-provider exchange first.
- **Most important fixes:** R-MNT-01 (CalDAV bypass), R-PPL-01/02/03 (security), R-MNT-02/03/05 and R-PPL-07 (one-sided contracts), R-PPL-04 and R-MNT-04 (People↔Maintenance handoffs).
